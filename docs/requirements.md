## 1. 프로젝트 배경 및 목적

개인 개발 프로젝트를 진행할 때 발생하는 버그와 할 일(Task)을 메모장이나 구두로 관리하면 누락·중복이 빈번하게 발생한다. 이를 해결하기 위해 브라우저에서 바로 사용할 수 있는 경량 이슈 트래커를 개발한다.

본 프로젝트는 동시에 **바이브코딩(AI 보조 개발) 방법론의 효과를 실증**하는 실습 과제이기도 하다. AI 도구(Claude)를 각 개발 단계에서 적극 활용하고, 그 과정과 결과를 기록한다.

## 3. 기능 요구사항 (Functional Requirements)

### FR-01. 이슈 생성
- **설명:** 사용자는 새로운 이슈를 생성할 수 있다.
- **입력 항목:**
  - 제목 (필수, 최대 100자)
  - 설명 (선택, 최대 500자)
  - 우선순위: Low / Medium / High / Critical (기본값: Medium)
  - 태그: Bug / Feature / Improvement / Question (다중 선택 가능)
- **출력:** 이슈 목록에 신규 항목이 추가된다.
- **우선순위:** 필수 (Must Have)

### FR-02. 이슈 목록 조회
- **설명:** 사용자는 등록된 모든 이슈를 목록 형태로 볼 수 있다.
- **표시 항목:** 제목, 상태, 우선순위, 태그, 생성일
- **기본 정렬:** 최신 생성 순 (내림차순)
- **우선순위:** 필수 (Must Have)

### FR-03. 이슈 상태 변경
- **설명:** 사용자는 이슈의 상태를 변경할 수 있다.
- **상태 흐름:**  
  `Open` → `In Progress` → `Resolved` → `Closed`  
  (단, 어느 상태에서든 `Closed`로 직접 전환 가능)
- **우선순위:** 필수 (Must Have)

### FR-04. 이슈 필터링
- **설명:** 사용자는 상태 또는 우선순위 기준으로 이슈를 필터링할 수 있다.
- **필터 기준:**
  - 상태별 필터 (All / Open / In Progress / Resolved / Closed)
  - 우선순위별 필터 (All / Critical / High / Medium / Low)
- **우선순위:** 필수 (Must Have)

### FR-05. 이슈 수정
- **설명:** 사용자는 기존 이슈의 내용을 수정할 수 있다.
- **수정 가능 항목:** 제목, 설명, 우선순위, 태그
- **우선순위:** 필수 (Must Have)

### FR-06. 이슈 삭제
- **설명:** 사용자는 이슈를 삭제할 수 있다.
- **조건:** 삭제 전 확인 다이얼로그를 표시한다.
- **우선순위:** 필수 (Must Have)

### FR-07. 데이터 영속성
- **설명:** 브라우저를 새로고침하거나 재시작해도 데이터가 유지된다.
- **구현 방식:** localStorage
- **우선순위:** 필수 (Must Have)

### FR-08. 이슈 검색 *(Nice to Have)*
- **설명:** 제목 또는 설명 내 키워드로 이슈를 검색할 수 있다.
- **우선순위:** 선택 (Nice to Have)

## 4. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01. 성능
- 이슈 100건 이하 기준, 목록 렌더링 시간 < 100ms

### NFR-02. 사용성
- 별도 회원가입/로그인 없이 즉시 사용 가능
- 모바일 브라우저에서도 기본 동작 가능 (반응형 레이아웃)

### NFR-03. 유지보수성
- 컴포넌트 단위로 모듈화하여 각 기능의 독립성 확보
- 커스텀 훅(custom hook)으로 비즈니스 로직과 UI 분리

### NFR-04. 호환성
- 최신 Chrome, Firefox, Edge 브라우저 지원

### NFR-05. 데이터 안전성
- localStorage 저장 실패 시 사용자에게 경고 메시지 표시
